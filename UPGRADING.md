# NVL Light migration

Requires PHP 8.4 and Laravel 13. Replace the previous checkout/contact Actions with `BillingCheckout::start` and `BillingContacts::update`. Checkout sessions and access snapshots are documented native arrays. Consumers own transport, response resources and any application DTOs.

The deprecated Tenancy bridge, package webhook controller and route are removed. Use native ownership admission and an application webhook endpoint calling `BillingWebhooks::process($rawPayload, $signature)`. Signature verification and transactional replay handling remain inside the service.

Keep existing provider identities, pending attempts and historical receipts when adopting populated storage. Billing still requires Cashier and Stripe. Configure host management and system-operation policies explicitly. See the [service reference](README.md).

Apply `2026_11_01_174311_nvl_billing_bind_checkout_request_identity.php` on the canonical Billing connection before deploying Checkout callers. The additive migration retains all existing rows and leaves historical `pending_checkout_request_hash` values null. Active attempts with no verified hash now fail with `checkout_conflict`, including cached sessions, until their original expiry; do not guess their former URLs or reset/reuse their provider keys. Existing provider sessions remain provider-owned. New attempts bind the complete public request, stable account/contact identity, saved trial/expiry and gateway-affecting configuration under the account lock. Retry the identical inputs and configuration after an uncertain provider outcome. Changed inputs require waiting for expiry or separately completing the provider's reviewed cancellation/expiry procedure. No attempt is automatically cleared or silently rebound.

Enabled Billing can boot without a webhook signing secret so `nvl:billing:doctor --strict` can report it. Webhook processing continues to reject a missing secret before signature or owner processing. Keep strict Doctor successful before enabling financial traffic.

BillingAccount now hides `stripe_id`, `pending_checkout_url`, `pending_checkout_attempt_id`, `pending_checkout_session_id` and `pending_checkout_request_hash` from default array/JSON serialization. Native direct access and Checkout responses remain unchanged. Replace generic account serialization with authorized host resources; do not re-expose the pending capability URL or recovery metadata to preserve an accidental response shape. Retained financial foreign keys, deduplication receipts and fixed entitlement states remain explicit [host policy obligations](README.md#retained-history-and-host-policy).

Install and enable `nvl/ownership` before invoking owner-facing Billing services, then complete reviewed Billing adoption. Disabled installations can boot without the optional runtime; an unscoped Billing mode is not supported. The account lifecycle migration relaxes the historical `tenant_id` requirement and adds `provider_deleted_at` before adoption. Its rollback preserves historical facts by requiring a reviewed retirement migration. Billing migrations now inherit the Core connection consistently with the models instead of consulting retired Tenancy configuration.

Inject concrete `BillingAccess` and `BillingPortal` services in place of the removed `BillingAccessContract` and `BillingPortalContract`. Keep `BillingGateway`, `SubscriptionReader` and `BillingManagementAccess` for provider and host extension. Configure exact HTTPS return hosts under `nvl-billing.checkout.return_hosts` for Checkout and Portal. Reconciliation now refuses ambient transactions and concurrent local changes instead of applying stale provider facts. The service-name changes require no provider identity conversion. Apply the account lifecycle migration described above before native Billing adoption.

Apply `2026_11_11_090000_nvl_billing_order_customer_updates.php` on the canonical Billing connection. It adds the nullable `provider_customer_updated_at` account column; existing accounts accept their next `customer.updated` event and later ignore older ones. `nvl:billing:doctor --strict` fails on `customer_event_order_schema` until the column exists.

Enabled Billing now suppresses Cashier's routes by default. If the application relied on Cashier's `/stripe/webhook` or payment routes while Billing was enabled, either move Stripe to the application endpoint that calls `BillingWebhooks::process()` (recommended) or set `nvl-billing.adoption.keep_cashier_routes` to `true` and review the `adoption.cashier_webhook_route` Doctor warning. `nvl-billing.adoption.cashier_routes` is unchanged.

`migrate:rollback`, `migrate:refresh` and Laravel's `DatabaseMigrations` trait now work with Billing migrations loaded. The account lifecycle and Checkout identity migrations drop their columns on rollback; in production they still refuse while the accounts table holds rows, so retire populated storage through a reviewed forward migration.
